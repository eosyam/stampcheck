Why your email looks broken in Outlook (and how to fix it)

By Eray, who builds Stampcheck · Published 4 November 2026

Short answer: classic Outlook for Windows does not use a browser to show HTML email. It uses Microsoft Word's rendering engine, which ignores flexbox, CSS grid, max-width, most background images and border-radius.

The fix is old-school but reliable: lay out with tables, inline your styles, give columns fixed widths, and wrap anything fluid in Outlook-only conditional code.

Why Outlook is different

Gmail, Apple Mail and Outlook on the web all show email with a browser engine, so modern CSS mostly works. Classic Outlook for Windows (the desktop app many companies still run) hands the same HTML to Word. Word was built to lay out documents, not web pages, so it supports only a small, older subset of HTML and CSS and silently drops the rest.

The new Outlook for Windows is built on Outlook on the web and renders much closer to a browser. Until your readers have all moved to it, though, an email still has to survive classic Outlook.

The six things that break most often

1. Flexbox and grid layouts collapse

Word ignores display: flex and display: grid. Columns stack, gaps disappear and items stretch to full width.

Fix: build columns with tables. Use role="presentation" so screen readers don't announce them as data tables.

<table role="presentation" width="600" cellpadding="0" cellspacing="0" border="0">
  <tr>
    <td width="300" valign="top">Left column</td>
    <td width="300" valign="top">Right column</td>
  </tr>
</table>

2. The email stretches across the whole window

Word ignores max-width, so a container set to width: 100%; max-width: 600px becomes as wide as the reading pane.

Fix: keep the fluid container for other clients and add a fixed-width "ghost table" that only Outlook sees:

<!--[if mso]>
<table role="presentation" width="600" align="center"><tr><td>
<![endif]-->
<div style="max-width:600px; margin:0 auto;">
  …your email…
</div>
<!--[if mso]>
</td></tr></table>
<![endif]-->

3. Buttons lose their shape

border-radius is ignored and padding on links is unreliable, so a rounded button turns into a flat, cramped text link.

Fix: put the padding and background on a table cell instead of the link, and accept square corners in Outlook. If rounded corners matter, a VML <v:roundrect> inside an <!--[if mso]> block draws a real rounded button for Outlook only.

4. Background images vanish

CSS background-image doesn't show in classic Outlook. Text that was meant to sit on a photo ends up on a blank (often white) area, sometimes unreadable.

Fix: always set a solid background-color that works with the text on its own. For a real image behind text in Outlook you need VML (<v:rect> with a <v:fill>), again inside an Outlook-only conditional.

5. Spacing is off

Margins on block elements, padding on <div>s and <p>s, and CSS shorthand in some properties are handled inconsistently. The result is uneven gaps or text pressed against edges.

Fix: create space with padding on <td> cells, and use spacer rows or cells with an explicit height when you need a fixed gap.

6. Fonts turn into Times New Roman

When a web font can't load, classic Outlook may skip your fallback stack and show Times New Roman.

Fix: keep web fonts out of the Outlook path. Wrap the @font-face or font <link> in <!--[if !mso]><!--> … <!--<![endif]--> and make sure every font-family ends with a safe system font such as Arial.

How to check before you send

  1. Run the HTML through a checker that knows Outlook's quirks. It is faster than guessing which of the six problems you hit.
  2. Fix what is marked as breaking first: layout and width problems affect every Outlook reader, cosmetic ones only some.
  3. Send one real test to an Outlook for Windows account before a large send, especially if you used VML.

Frequently asked questions

Why does my email look fine in Gmail but broken in Outlook?

Because classic Outlook for Windows renders it with Word instead of a browser engine. Gmail supports the modern CSS you used; Word drops it.

Does the new Outlook for Windows have the same problems?

Much less. It renders close to Outlook on the web. The problems above are mainly a classic Outlook issue, which is still widespread in companies.

Do I have to build the whole email with tables?

The structure, yes: rows and columns. Inside cells you can still use normal text, images and links with inline styles.

How can I test in Outlook if I don't have it?

Use a checker to catch the known problems, then borrow one real Outlook for Windows inbox for a final test of anything important.
